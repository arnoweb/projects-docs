The Problem

Most catalogs still show the same "related items" to every visitor — a rule set that is configured once and never updated with what people actually click, view or buy. A new visitor, a new product, or a returning user with a full basket all see the exact same shelf.

The Solution

Likyly combines three recommendation strategies into one hybrid engine:

  • Content-based — TF-IDF plus sentence-transformer embeddings capture thematic similarity from product text, computed the moment a product is ingested, so it's recommendable immediately (no waiting for a retraining cycle).
  • Collaborative — implicit ALS trained on real interactions, weighting a purchase more than a view, with no fabricated ratings.
  • Weighted hybrid — content and collaborative scores blend through a tunable parameter, adjustable per request, and it works from the first pageview — with or without an account.

It is a multi-tenant SaaS, live at likyly.com. Each customer's catalog, events and models are isolated, and each customer gets its own model: its data never trains a shared one. Models retrain on their own and go live only when they beat the current version.

Integrated in Minutes, by Your Own AI Assistant

Integration is usually the slowest part of buying a recommendation engine: reading the docs, mapping the catalog, wiring the tracking events. LIKYLY treats developer experience as part of the product. Like PostHog's install wizard, one command installs it:

$ npx @likyly/wizard
  • One command — it detects the framework, installs the right SDK, signs the developer in and writes the keys in the right place. Nothing is overwritten, and it works on its own git branch.
  • The AI assistant does the integration — an MCP server lets Claude Code, Cursor or VS Code connect the catalog, configure the recommendation block, write it into the real components and add the tracking events.
  • Plain-language prompts — "show 4 related products on the product page, no out-of-stock items" replaces a configuration screen.
  • Checked, not guessed — LIKYLY verifies the integration from the data it actually receives, then reports what each block served and earned.

Why Not Just Call an LLM per Request?

It's tempting to ask a general-purpose LLM "what should this user see next?" on every request. Likyly deliberately doesn't: specialized models (TF-IDF, embeddings, ALS), tracked and versioned with MLflow, are precomputed or resolve in a few tens of milliseconds — cheap to run, private to each customer, and deterministic. AI is used where it pays off: helping the developer integrate, not answering every visitor. A generic LLM call is billed per request, adds seconds of latency at e-commerce traffic scale, and depends on a third-party provider for a decision that needs to be instant and explainable.

Who It's For

SaaS products, e-commerce catalogs and content platforms (products, films, articles, cultural content) that want real personalization without shipping user or catalog data to a third-party LLM on every request. It plugs into Shopify, WooCommerce, any REST API or a CSV file, and ships 8 official SDKs (JS/TS with React components, PHP, Python, Java, .NET, Go, Ruby, Rust).
