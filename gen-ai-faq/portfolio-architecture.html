// PROJECT ID: 003 — GENERATIVE AI KNOWLEDGE ASSISTANT

GEN AI FAQ // ARCHITECTURE

How raw FAQ pairs become a fine-tuned sentence-transformer, and how retrieval plus optional generation serve every query.

sentence-transformers PyTorch autotrain-advanced Hugging Face Hub Streamlit

Pipeline

01
Data
Raw FAQ question/answer pairs (JSONL) are split into train/validation sets.
02
Fine-tuning
An autotrain-advanced pipeline, run on a local backend and driven entirely by a config file, fine-tunes a mpnet-base-v2 sentence-transformer for 2 epochs on the FAQ's own question/answer pairs.
03
Model registry
The fine-tuned model is pushed privately to the Hugging Face Hub; consuming apps load it through SentenceTransformer(path), which resolves either to the public base checkpoint or the private fine-tuned repo.
04
Serving (retrieval)
FAQ answers are encoded once and cached per language; each incoming question is encoded on the fly and ranked against them by cosine similarity. An optional LLM call generates a natural-language reply from the top match — generation happens only at the very end of the chain, on demand.
05
Evaluation
A dedicated comparison script measures MRR and Recall@1/3/5, base model vs. fine-tuned, globally and per language — so the fine-tuning's impact is measured, not assumed.

Why Fine-Tune Instead of a Bigger Model

Training and serving stay strictly separated: fine-tuning runs locally from a single config file, and only the resulting model is pushed to the Hub — the serving environment never needs the training environment. A small encoder fine-tuned on the FAQ's own vocabulary retrieves the right answer for less than a large general-purpose model call would cost per query, reserving the LLM for the final generation step only.
