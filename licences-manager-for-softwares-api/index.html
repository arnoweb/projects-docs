API de licences multi-éditeurs

Une API de licences qui protège vos revenus — sans vous enfermer dans le cloud de quelqu'un d'autre

Un jeu, un plugin, une application SaaS ou un logiciel installé a souvent besoin d'une simple clé de licence pour débloquer ses fonctionnalités premium. Cette API auto-hébergée gère l'activation, la désactivation et l'administration de ces licences pour plusieurs éditeurs à la fois — chacun strictement isolé des autres — avec des jetons signés Ed25519, vérifiables hors-ligne par le logiciel client.

✓ Auto-hébergée, sur votre propre infrastructure ✓ Multi-éditeurs : isolation stricte des données ✓ Vérification de signature hors-ligne (Ed25519) ✓ Rien de sensible stocké en clair (HMAC-SHA256) ✓ Apache-2.0, aucun verrouillage propriétaire

01

Cas d'usage

Cinq profils d'éditeurs directement couverts par le modèle multi-tenant actuel.

Éditeurs de jeux & DLC

Freiner la redistribution de clés piratées

ContexteUn studio indépendant vend un jeu, des mods ou du DLC et veut limiter chaque licence à quelques machines, sans construire son propre backend.
ProblèmeUne clé codée en dur dans le binaire se retrouve partagée sur un forum en quelques jours.
Solution/activate avec quota d'appareils par licence et jeton signé Ed25519, vérifié hors-ligne à chaque lancement.
Valeur : le partage sauvage de clés devient auto-limitant, sans SDK anti-piratage lourd.
Éditeurs SaaS & logiciels desktop

Débloquer les fonctionnalités Pro par palier d'abonnement

ContexteUne app SaaS ou desktop veut réserver certaines fonctionnalités aux abonnés Pro ou Enterprise.
ProblèmeConstruire un système de licences maison prend des semaines et se trompe souvent : secrets qui fuitent, aucune révocation possible.
SolutionAPI d'administration scopée par éditeur — créer, activer, désactiver une licence instantanément, branchée sur n'importe quel système de facturation.
Valeur : le contrôle d'accès Pro livré en un jour, pas en un trimestre.
Marketplaces de plugins & add-ons

Un seul backend de licences pour tout un catalogue

ContexteUn éditeur vend de nombreux petits plugins ou add-ons sur une marketplace (DAW, CAD, design…).
ProblèmeChaque add-on réinvente sa propre vérification maison — ou n'en a aucune.
SolutionUne API multi-éditeurs unique, un compte éditeur par gamme de produits, le même contrat /activate partout.
Valeur : une protection cohérente sur tout le catalogue, sans multiplier les backends.
Logiciels d'entreprise & on-premise

Contrôler les licences sans dépendre en permanence du réseau

ContexteDes clients grands comptes font tourner le logiciel sur des réseaux fermés, avec un accès internet occasionnel.
ProblèmeUn DRM rigide qui exige un contact serveur permanent casse dès qu'il tourne en environnement restreint ou isolé.
SolutionJeton signé mis en cache et vérifié hors-ligne via la clé publique Ed25519 ; re-validation uniquement à l'expiration (1h par défaut, configurable).
Valeur : les clients grands comptes continuent de travailler, l'éditeur garde le contrôle.
Plateformes multi-marques

Provisionner une nouvelle marque éditeur sans tout re-architecturer

ContexteUn opérateur fait tourner la plateforme pour plusieurs studios ou marques sous un même toit.
ProblèmeUne table de licences partagée fait courir le risque qu'une marque voie les données d'une autre, ou qu'une fuite touche tout le monde.
SolutionL'API plateforme provisionne un nouvel éditeur, avec ses propres jetons client/admin, en un seul appel ; l'isolement est appliqué à chaque requête.
Valeur : une nouvelle marque onboardée en quelques minutes, le rayon d'impact d'une fuite reste limité à un éditeur.

03

Fonctionnalités

Ce que l'API fait, concrètement.

Isolation multi-éditeurs

Chaque utilisateur, licence et activation est scopé par éditeur au niveau de la requête — un jeton admin ne voit jamais les données d'un autre éditeur.

Vérification de signature hors-ligne

Les jetons sont signés Ed25519 ; le logiciel client vérifie localement contre une clé publique mise en cache, sans aller-retour serveur à chaque lancement.

Quotas d'activation par appareil

Chaque licence applique un max_activations ; désactiver un appareil libère un slot pour un autre.

Débit limité par utilisateur final

/activate est throttlé par (éditeur, email), pas seulement par jeton d'éditeur — un utilisateur abusif ne peut pas noyer le trafic des autres.

Rotation de clé sans casser les anciens jetons

Les clés vivent en base (table signing_keys) avec un kid ; la rotation retire l'ancienne clé de la signature mais la garde valide pour vérifier les jetons déjà émis.

Auto-hébergeable, Apache-2.0

Tourne sur votre propre infrastructure (Docker Compose, Caddy, Postgres) — pas de coût à l'activation vers une SaaS de licences tierce.

04

Sécurité

Une API de licences n'a de valeur que si elle est elle-même difficile à contourner.

Rien en clair

Clés de licence et jetons éditeur sont hashés (HMAC-SHA256 salé) avant d'atteindre la base — jamais stockés en clair.

Jetons vérifiables hors-ligne

Chaque jeton d'activation est signé Ed25519 ; le logiciel client le vérifie localement, sans dépendre du serveur à chaque lancement.

Fenêtre de validité limitée

Un jeton expire au bout d'1h par défaut ; passé ce délai, l'app rappelle /activate — la révocation finit donc toujours par se propager.

Journal d'audit

Chaque mutation admin ou plateforme (création, activation, rotation) est tracée : acteur, action, cible, IP, horodatage.

05

Valeur métier

Beaucoup de logiciels sortent encore sans aucun système de licences — une clé codée en dur, ou rien du tout. Ça fonctionne jusqu'au premier remboursement à traiter, ou à la première clé qui circule librement sur un forum.

Sans système de licence
  • Une clé fuitée ou copiée-collée débloque le produit pour toujours, sur un nombre illimité de machines
  • Impossible de révoquer l'accès après un remboursement sans reconstruire le logiciel
  • Chaque produit réinvente sa propre vérification maison, jamais auditée
  • Les clients sur réseau fermé sont soit bloqués, soit contournés
Avec cette API
  • Quota par appareil + vérification hors-ligne rend le partage sauvage de clé auto-limitant
  • POST /admin/licenses/enable désactive une licence immédiatement, sans nouvelle build
  • Un seul backend audité, multi-éditeurs, pour tous les produits vendus
  • Les jetons se vérifient localement — fonctionne avec une connectivité limitée, et expire quand même
