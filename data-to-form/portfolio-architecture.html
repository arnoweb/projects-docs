// PROJECT ID: 003 — SAAS FORM AUTOMATION

DATA TO FORM // ARCHITECTURE

A full Node.js stack: the automated browser is streamed live into the user's tab (CDP screencast), and the LLM is only the 4th and last level of matching.

Node.js · Express CDP Screencast WebSocket Playwright SheetJS SQLite ONNX Runtime

4-Level Matching Cascade

Each spreadsheet column walks through these levels in order — as soon as one answers with enough confidence, the rest are skipped.

01
Synonyms
A dictionary of roughly 190 known labels (FR/EN/ES) instantly recognizes common columns — name, email, address, date of birth, and similar.
02
Memory
Matches already validated for a given form — by a user, or by a previous LLM call — are cached and reused automatically the next time (threshold ≥ 0.92, source: cache / user).
03
Local encoder (ONNX)
A quantized Xenova/all-MiniLM-L6-v2 model (~23MB) runs in-process — no network call — and ranks candidates by cosine similarity between the column's embedding and each form field's embedding.
04
LLM — last resort
Rare: only the columns still unresolved after the first three levels are sent to an LLM (local model, or Anthropic / OpenAI / Hugging Face with your own key).

Live Browser Streaming (CDP Screencast)

The browser that fills the form runs on the server, yet the user sees it and controls it live in their own tab. There is nothing to install and no VNC client. Playwright drives a headed Chromium inside the Docker container, which renders to a virtual screen (Xvfb). The Chrome DevTools Protocol command Page.startScreencast sends JPEG frames, which go to the page over a WebSocket and are drawn on a <canvas>.

FIG. 1 — The browser runs on the server; the user sees and steers it from their own tab.

Each frame is acknowledged (screencastFrameAck), so a slow client slows the stream down instead of freezing it. The screencast stops at every navigation, so it starts again automatically. Clicks, typing and key presses go back over the same WebSocket and Playwright replays them on the page. The user can log in or solve a captcha by hand, then let the automatic filling continue.

One Node.js Stack

There is no Python service. One Node.js process (Express) serves the site, runs the WebSocket sessions, drives Playwright and runs the ONNX encoder in-process through Transformers.js. The source file is parsed with SheetJS and is never written to disk. Validated mappings are stored in SQLite (better-sqlite3) and reused on later runs. LLM calls are traced in Langfuse.
