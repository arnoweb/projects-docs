Remplissage de formulaires piloté par IA

Le pont entre votre Excel et n'importe quel formulaire web, sans API

Des milliers d'outils métier — logiciels de billetterie, extranets fédéraux, back-offices e-commerce, portails immobiliers, CRM médico-sociaux — n'exposent aucune API d'import. La seule porte d'entrée reste leur formulaire web. DataToForm ouvre une vraie fenêtre de navigateur sur ce formulaire, comprend ses champs, et les remplit ligne par ligne à partir d'un fichier Excel — sans jamais cliquer sur « Envoyer » à la place de l'utilisateur.

Si aucun des trois niveaux locaux n'avait été assez confiant, le LLM aurait été sollicité en dernier recours, sur la seule base des noms de colonnes et des labels — jamais des données réelles.

Validation par l'utilisateur
L'utilisateur accepte, corrige ou ignore la suggestion — champ par champ, avant tout remplissage réel. Rien n'est écrit dans le formulaire sans ce mapping validé.

Une fois validé, le mapping est rejoué automatiquement pour chaque ligne du fichier — la soumission finale reste toujours un clic humain.

03

Fonctionnalités

Ce que l'application fait, concrètement.

Fenêtre de navigateur réelle

Playwright ouvre Chromium sur l'URL du formulaire cible — pas de simulation, le formulaire réel est inspecté et rempli.

Connexion gérée par l'utilisateur

Si le formulaire est derrière une authentification, l'utilisateur se connecte lui-même dans la fenêtre ; aucun mot de passe ne transite par le serveur.

Détection automatique des champs

Texte, select, multi-select, checkbox, radio, y compris les selects en cascade — sans configuration préalable.

Matching à 4 niveaux, avec score de confiance

Synonymes, cache appris, puis similarité sémantique locale ; chaque champ reçoit une colonne Excel suggérée et un score. L'utilisateur valide, corrige ou ignore avant tout remplissage.

Extraction Excel intelligente

Pour les documents non tabulaires (plans de charge, rapports), un appel LLM ponctuel détecte et structure les données avant le mapping.

Provider LLM interchangeable, sollicité en dernier recours

Ollama local et gratuit par défaut ; Anthropic, OpenAI ou HuggingFace disponibles avec votre propre clé — appelés seulement quand le matching local ne suffit pas.

Comment le mapping reste rapide et (presque) gratuit : chaque colonne Excel traverse jusqu'à quatre niveaux, dans l'ordre — dès qu'un niveau répond avec assez de confiance, les suivants sont sautés.
  • Niveau 1 — Synonymes : un dictionnaire d'environ 190 libellés connus (FR/EN/ES) reconnaît instantanément les colonnes courantes (nom, email, adresse, date de naissance…)
  • Niveau 2 — Mémoire : les correspondances déjà validées pour un formulaire (par un utilisateur ou par l'IA) sont mémorisées et réutilisées automatiquement la fois suivante
  • Niveau 3 — Compréhension locale : un modèle d'analyse de texte compact, exécuté sur le serveur sans appel externe, rapproche les libellés qui se ressemblent sans être identiques
  • Niveau 4 — IA en ligne, si nécessaire : seules les colonnes encore sans correspondance après les trois premiers niveaux sont envoyées à un LLM — et son résultat est mémorisé pour ne plus jamais y revenir
En pratique, une fois un formulaire déjà rencontré, la quasi-totalité des colonnes se résout aux niveaux 1 à 3 — l'appel à un LLM externe devient l'exception, pas la règle.
04

Valeur métier

La saisie manuelle dans un formulaire web sans API n'est pas seulement lente : elle mobilise du temps humain qualifié sur une tâche mécanique, et chaque copier-coller est une occasion d'erreur.

Saisie manuelle, champ par champ
  • Chaque ligne du tableur est recopiée à la main dans le formulaire cible
  • Le temps passé croît linéairement avec le nombre de lignes
  • Aucune trace du mapping utilisé — il repose sur la mémoire de la personne qui saisit
  • Risque d'erreur de frappe ou de champ oublié à chaque ligne
DataToForm
  • Le mapping colonnes → champs est établi une fois, validé, puis rejoué automatiquement
  • Le temps de traitement d'une ligne supplémentaire devient marginal
  • Le mapping validé est explicite et réutilisable pour le même formulaire
  • La relecture reste humaine, ligne par ligne, avant tout envoi

06

Pourquoi une validation humaine plutôt qu'un bot autonome ?

Beaucoup d'outils d'automatisation de formulaires promettent un remplissage — et un envoi — totalement autonomes. DataToForm fait un choix différent, volontairement : l'IA propose, l'utilisateur valide et envoie.

Bot qui remplit et soumet seul
  • Une erreur de mapping se propage à toutes les lignes avant d'être repérée
  • Un formulaire soumis à tort peut être irréversible (paiement, inscription, dossier officiel)
  • Aucun point de contrôle humain avant l'envoi
  • La confiance du client dans l'outil dépend d'une exécution parfaite, sans marge d'erreur
DataToForm
  • Le mapping est validé champ par champ avant le premier remplissage réel
  • Chaque ligne remplie est relue par l'utilisateur avant l'envoi
  • La soumission reste un geste volontaire, à chaque ligne
  • /api/fill-current-row n'accepte aucun sélecteur de soumission, par conception — l'automatisation totale du clic « Envoyer » n'est pas une option de configuration, elle est absente du code
07

Garanties & limites actuelles

Ce que l'application garantit, et ce qu'elle ne fait pas — pour évaluer le fit sans surprise.

Garanties par conception :
  • Le fichier Excel est parsé en mémoire, jamais écrit sur disque ni envoyé à un tiers
  • Le mapping colonnes → champs se résout d'abord en local (synonymes, mémoire, similarité) ; un LLM n'est sollicité qu'en dernier recours, pour les colonnes restées sans correspondance
  • Quand un LLM est sollicité, seuls les noms de colonnes et les labels de champs lui sont envoyés — jamais le contenu réel des lignes
  • Le formulaire n'est jamais soumis automatiquement, à aucune étape
  • Le LLM local (Ollama) est utilisé par défaut pour ce dernier recours, sans coût variable ni sortie de données
